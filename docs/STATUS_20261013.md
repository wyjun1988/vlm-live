what is verified where, the open risks, and the decisions the next results will settle. Sources: `outputs/run3_*`
(REPORT.md of 10-13, the live bundle), `docs/BRAINSTORM.md` (I-45..I-49), `docs/SERVER_RUN3.md`,
`docs/SERVER_RUN4_PREP.md`.

## 4. Found and fixed in this review

- **fla's kernels were never installed on the server.** Since fla 0.5, `flash-linear-attention` is the layers only;
  the kernels are the separate package `fla-core`, which `pip install --no-deps` leaves out. p0 and the prep script
  install both (pinned 0.5.2) and test `import fla.ops.gated_delta_rule`. transformers >= 5.16 would not have used
  them anyway without `LIVE3R_GDN=fla` (`src/live3r/model/kernels.py`).
- **The prompt form.** `data.image_newline` is a training-only flag; the evaluation prompt never puts "\n" after an
  image block, in the 10-12 runs as in the live ones - the live-vs-oracle deltas are clean. The real mismatch is run 3
  trained with the newline (5d963f6) and evaluated without it; `eval_vsi_local.py --image-newline` evaluates in the
  trained form (`ROLE=format`).

## 5. Open risks and items

1. **The general-ability gate may fail.** The mix has no general video QA beyond llava_hound (64k). A VideoMME drop
   beyond −1.0 against the base means run 4 mixes general data in.
2. **The live design's latency is unmeasured.** REPORT.md's latency rows are the gated arm at 32 keyframes
   (question-only TTFT 170 ms). plain at 128 frames (192 tokens a frame, ~25k visual tokens) needs its own numbers,
   including the re-prefill when the buffer halves.
3. **The serving session's visual-token cap is 16,384** (`stream.max_visual_tokens`, `serve/session.py`; not applied
   in evaluation). At 192 tokens a frame that is 85 frames - below the 128 the design wants. Raise it before a demo.
4. **gated's live rows carry a small confound:** run 3 trained CUT3R in fp32, the 10-13 live evaluations ran it under
   bf16 autocast. plain is unaffected.
5. **live 32 holds fewer than 32 frames on videos shorter than 32 s** (the 1 fps grid); part of its −0.8 vs oracle 32.
6. **Run 3's training settings differ from today's code:** 200 LoRA modules (248 now), the earlier SPAR mark rules,
   the newline form, CUT3R fp32. A run 4 on today's code differs from run 3 in these as well as in what it tests.
7. **VSI-590K:** each source keeps its own terms (the card is Apache-2.0) - confirm internal use; ~150 GB free on
   `/group-volume` at the peak; a layout mismatch stops at the report table.
8. **control stopped at 6,180 / 22,218 steps (its node went away); gated_wn never started.** Both skipped by design
   now that the key comparison is answered.
9. Local working tree: the voice front-end work of the parallel session (`docs/VOICE_FRONTEND.md`,
   `src/live3r/serve/voice.py`, ...) is committed separately from the run-3 work.
