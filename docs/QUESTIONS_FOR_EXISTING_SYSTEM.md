# 기존 73.3 시스템에 물어볼 것

코드를 가져올 수 없으므로, 아래 항목을 그쪽 LLM/담당자에게 물어 채워주면
Live3R 이 **같은 데이터·같은 운영점**에서 비교 가능해진다.
답이 없으면 추측으로 맞춰야 하고, 그러면 격차의 원인을 못 가린다.

우선순위 순. **P0 없이는 학습 코드를 확정할 수 없다.**

## P0 — 데이터 (이게 제일 급하다)

1. 학습데이터의 **JSON 스키마 실제 예시 3개** (민감정보 제외).
   특히: 영상 경로 필드명 / 대화 포맷 / 프레임 인덱스를 미리 박아두는지 / 태스크 라벨
2. 총 샘플 수와 **구성비** (VSI-590K? 자체 생성? 일반 비디오 SFT 를 섞는가? 몇 %?)
3. 영상 소스와 로컬 경로 규약 (ScanNet/ScanNet++/ARKitScenes, mp4 인가 프레임 폴더인가)
4. **일반 데이터 리플레이를 섞는가?** 섞는다면 무엇을 몇 %로.
   (섞지 않고도 VideoMME 가 안 떨어졌다면 그 자체가 중요한 정보다)

## P0 — 운영점 (숫자 비교의 전제)

5. **프레임 몇 장**을 VGGT 에 넣는가? 어떻게 고르는가(균등/fps/키프레임)?
6. 프레임 **해상도**와 VGGT 입력 크기
7. LLM 이 실제로 받는 **비전 토큰 수** (1문항당)
8. VGGT 체크포인트 (facebook/VGGT-1B 그대로인가 사내 판본인가)

## P1 — 융합·학습 레시피

9. 기하 토큰을 LLM 에 **어떻게 넣는가**?
   (a) 입력 직전 1회 concat/cross-attn  (b) 디코더 여러 깊이 residual(deepstack)  (c) 기타
   (b) 라면 **VGGT 어느 레이어 → LLM 어느 레이어**인지
10. 카메라/포즈 토큰을 따로 노출하는가?
11. 학습 단계 구성 (프로젝터 정렬을 따로 두는가? LoRA rank/타깃 모듈? lr/epoch?)
12. 프로젝터 구조 (MLP? merger? zero-init 인가?)

## P1 — 점수 재현 조건

13. 73.3 의 **VSI-Bench 세부 8태스크 점수**
    (어느 태스크에서 강한지 알아야 스트리밍에서 어디가 깎이는지 예측된다)
14. 평가 프레임워크 (lmms-eval 인가 자체인가? 자체면 프롬프트 템플릿)
15. VideoMME 등 **일반 벤치 점수** (우리 회귀 게이트의 기준선이 된다)
16. thinking off 를 어떻게 껐는가 (chat template 플래그? 시스템 프롬프트?)
