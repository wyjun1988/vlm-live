# M2 로컬 실측 — 2026-09-24 (H100 이 막힌 동안)

머신: MacBook Pro M2 Max · 통합 메모리 34GB · MPS · torch 2.14 · transformers 5.16.1.
H100 이 막혀서 이 머신에서 할 수 있는 검증을 했다. **실가중치로 돌린 첫 결과들이다.**

**요약**
1. **입력 경로 = 공식 경로** — 4B bf16 로짓 Δ 0.0. zero-init 주입은 베이스와 Δ 0.0 (1절).
2. **서버에서도 터졌을 문제 7건** — thinking 기본값, CUT3R 로딩·로깅, gdown, S1 lr, LM 헤드 전 위치 로짓(메모리 8배), MPS 할당기 (2절).
3. **VSI 키프레임 선택 비용 없음** — 4B 60영상: halving 49.9 vs 오라클 48.6, Δ 95% [−1.7, +4.9]. 베이스 4B ≈ 50 (4절).
4. **게이트 1 교란** — 키프레임을 이미지로 주면 베이스가 답 형식을 어긴다 (4B 60영상: 이미지 24.7 vs 비디오 48.6, 선택형 전부 0점). → 기준선 = 베이스의 최선 형식으로 결정 (4절).
5. **지연** — 4B TTFT 의 94% 가 시각 프리필. 질문만 TTFT 0.41초 (M2). H100 추정 0.1~0.4초 (5절).
6. **S1 파일럿: 프로젝터가 기하가 아니라 답 형식을 배웠다** — 절제 판정 "신호로만 쓴다" (none 2.49 → real 0.93 ≈ shuffled 0.90). 4번과 같은 현상이 학습 쪽에서 (6절).
7. **대조 프로젝터로 확정** — 다른 샘플의 기하로 학습한 대조군이 홀드아웃 0.887 로 진짜 기하 쪽(0.928)과 구분 안 됨 (기하 내용의 가치 −0.04 ± 0.05). 이 규모에선 배운 게 전부 내용과 무관 (7절).
8. **S2 LoRA 파일럿 (4B, 905건)** — VSI 이미지 모드 44.1 (대조 42.3, 진짜 − 대조 +1.9 [−0.9, +4.4]). 형식은 고쳤지만 수치 추정이 데이터 분포로 쏠려 **베이스 최선 형식(48.6)보다 낮다** (8절).
9. **CUT3R 장면 지도 (제로샷)** — 지도 이미지의 순효과 **0** (−0.3 [−2.8, +2.4]): 측정 면적이 방 크기를 +13~19 올리지만 지도 이미지가 등장 순서·방향을 깎는다. 대신 **형식 지시 한 줄이 베이스를 +5.1 올린다** (이미지 모드 53.7). 질문만 TTFT 는 지도가 있어도 0.23초 (9절).

## 1. 실가중치 입력 경로 검증 — `scripts/check_real_weights.py`

같은 이미지·질문을 공식 프로세서 경로와 우리 경로에 넣고 비교했다.

| 모델 | 토큰열 | 픽셀 | 로짓 max\|Δ\| (우리 vs 공식) | 답 |
|---|---|---|---|---|
| Qwen3.5-0.8B fp32 | 동일 | 0 ~ 6e-8 | 9e-5 / 0.0 | 동일 |
| **Qwen3.5-4B bf16** | 동일 | 0 | **0.0 / 0.0** | 동일 (`'spatial42'`, `'red, left'`) |

예전 래스터 순서 버그(2026-09-23 수정)를 4B 에 넣어 보니: 글자 이미지에서 **빈 답**
(로짓 Δ 17, top-5 겹침 0/5), 원의 색·좌우는 맞혔다. → **세밀한 시각 정보만 망가뜨리고 대략적 정보는
살려두는** 버그였다. VSI 의 거리·크기 문항이 바로 그 세밀한 정보를 쓴다.

zero-init 기하 주입(훅 3회 작동): 베이스 대비 로짓 Δ **0.0** — 학습 전에는 베이스와 완전히 같다.

## 4. VSI-Bench 제로샷 — `scripts/eval_vsi_local.py`

프롬프트·채점은 lmms-eval vsibench 함수를 그대로 import. 학습 전이라 기하는 dummy
(zero-init → 주입량 정확히 0, 1절에서 실가중치로 확인). 키프레임 32장.
스모크: 영상 3개(scannetpp, 모든 문항 유형 포함) · 119문항 — **유형별 수치는 표본이 작아 거칠다.**

### Qwen3.5-0.8B (bf16)

| | halving-이미지 (라이브) | 오라클-이미지 | 오라클-비디오 |
|---|---|---|---|
| overall | 11.3 ~ 11.9 | 12.8 ~ 13.6 | **32.2** |
| 답 형식 실패율 | **55.5%** | **55.5%** | **0.0%** |

(범위 = 프리픽스 캐시 유무 두 번 실행. bf16 수치 오차로 일부 답이 갈린다 — 아래 참고)

- **키프레임 선택 비용**(halving − 오라클, 같은 이미지 모드): −0.9 / −2.3 점 → 작다.
  인과적 halving 이 오프라인 균등 추출을 거의 따라간다는 첫 실측 (표본이 작아 확정은 아니다).

  키프레임 32장을 이미지로 넣으면 0.8B 가 "간단히 답하라" 지시를 무시하고 설명을 시작한다
  (`"To determine the distance, we first identify..."`, `"Based on the provided images, ..."`)
  → 16토큰(태스크 설정)에서 잘려 채점 0. 비디오 모드에서는 `"C"`, `"0.1"` 처럼 짧게 답한다.

### ⚠️ 게이트 1 에 대한 함의

게이트 1 은 "같은 경로(이미지 모드)에서 베이스 대비 +1.0" 이다. 베이스가 이미지 모드에서
**답 형식 때문에** 손해를 보고 있으면, 학습이 공간 이해 없이 **"짧게 답하는 법"만 배워도**
게이트를 넘는다. → 게이트 1 의 기준선은 베이스의 **최선 형식**(이미지·비디오 중 높은 쪽)이어야 한다.
**→ 2026-09-24 채택.** `run_gate.sh` 가 베이스를 비디오 모드로도 재고 `check_gate.py --base-alt` 가 높은 쪽을 쓴다.
(기하 절제 평가는 이 교란에 안전하다 — 다른 샘플의 기하도 같은 프로젝터를 지나므로
형식 학습 효과는 shuffled 조건에도 똑같이 들어간다.)

라이브 설계(영상은 한 번 먹고, 질문은 질문 토큰만 처리)와 같은 구조다.

| | 캐시 없음 | 캐시 |
|---|---|---|

벌어진다 — 프리픽스를 따로 계산하면 DeltaNet 청크 경계·누적 순서가 바뀌고 bf16 유효숫자가
3자리 정도라서. 첫 토큰 top-1 은 일치(6/6)하지만 16토큰 생성 중 일부 답이 갈린다 (119문항 중
95~114개 일치). **버그가 아니라 수치 오차** — 비교하는 양쪽이 같은 경로를 쓰면 된다.

## 5. 지연 — 지연 모드 실측 (`bench_latency.py --mode deferred`)

실제 CUT3R · 키프레임 32 (비전 토큰 3,744) · 640×480 · 기하 stride 3 · M2 MPS.

| | Qwen3.5-0.8B | Qwen3.5-4B |
|---|---|---|
| 기하 프레임 (CUT3R) | 311 ms (최대 3.2fps) | 318 ms (최대 3.1fps) |
| **지연 모드 TTFT** | 3,508 ms | 11,964 ms |
| ↳ 키프레임 확정·기하 임베딩 | 266 ms | 333 ms |
| ↳ **비전 타워·LLM 시각 프리필** | **2,991 ms** | **11,220 ms** |
| **질문만 TTFT** (시각 프리픽스가 미리 캐시돼 있을 때) | **251 ms** | **410 ms** |
| TPOT | 23.5 ms | 39.6 ms |

- **TTFT 의 94% 가 질문과 무관한 시각 프리필이다.** 스트림 중에 미리 해두면 **M2 에서도 4B 가 0.41초.**
- **H100 에서는 지연 모드 그대로도 TTFT < 1s 일 가능성이 높다** (FLOPs 추정, 서버 실측 필요):
  4B 시각 프리필 = LLM 본체 3.57B × 2 × 3.8k 토큰 ≈ 27 TFLOP + 비전 타워 0.33B × 2 × 15k 패치 ≈ 10 TFLOP
  ≈ **37 TFLOP**. M2 는 11.2초 → 실효 3.3 TFLOPS. H100 bf16 이 실효 100~400 TFLOPS 면 **0.1~0.4초**.
  → 서버 목표(TTFT < 1s)에는 아래 증분 프리필이 **필수가 아니다.** 서버에서 `bench_latency.py --mode deferred`
  로 먼저 재고, 증분 프리필은 M2 같은 엣지 데모나 키프레임 예산을 크게 늘릴 때의 선택지로 둔다.
- 선택지 — **halving 을 고려한 증분 프리필**: 이미지 모드에서는 키프레임마다 비전 토큰이
  독립적으로 계산되므로 선택되는 순간 인코딩해 둘 수 있다. halving 이 프레임을 버리는 일은
  스트림 길이의 로그 횟수뿐이라, 그 사이에는 새 키프레임을 LLM 캐시에 **이어 붙이고**
  버릴 때만 다시 만든다 (선형 어텐션 층은 상태에서 프레임을 뺄 수 없어 재구성이 필요).
  → 질문 시점엔 질문 토큰만. 단 지금의 "버퍼 2배에서 질문 시점에 균등 32장" 규칙은 새 프레임마다
  고르는 집합이 바뀌어 이어 붙일 수 없다 — 규칙을 "버퍼 = LLM 이 보는 집합"으로 바꿔야 하고,
  그러면 평가 규칙도 같이 바뀐다. (비디오 모드는 2프레임이 한 블록이라 버릴 때 짝이 바뀌어
  더 번거롭다 — 이미지 모드를 지지하는 근거.)
- 기하 인코더(CUT3R)는 M2 에서 3fps 대 — 30fps 웹캠을 따라가려면 stride ≥10 이 필요하다.
  (60프레임 측정의 "실시간 추종 3.2fps" 는 초반에 halving 이 거의 모든 프레임을 키프레임으로 받아
  CUT3R 이 매 프레임 돈 과도기 값이다.) H100 + curope 에서는 훨씬 빠를 것.

## 5-1. 프로젝터 lr — 주입이 비전 표현을 압도한다

Sensenova 1k 에서 20스텝(샘플 1개씩) 동안 레이어 0 의 주입 비율(‖주입‖/‖비전 히든‖):

| lr | 5스텝 | 10스텝 | 15스텝 | 20스텝 |
|---|---|---|---|---|
| **1e-3** (예전 서버 문서의 S1 설정) | 4.0 | **15.6** | **30.3** | **20.6** |
| 1e-4 | 0.32 | 0.67 | 1.13 | 0.80 |
| 3e-5 | 0.12 | 0.21 | 0.31 | 0.22 |

레이어 1·2 는 1e-3 에서도 0.4~0.9 인데 **레이어 0 만 폭주**한다 — 잔차 스트림의 노름은 깊이에 따라
커지므로 레이어 0 출력이 가장 작고, 같은 크기의 주입이 상대적으로 가장 크다. LLaVA 식 프로젝터(비전 토큰을 **대체**)의 lr 관례(1e-3)를
**더하는** 구조에 쓰면 안 된다. → S1 기본 lr 을 **3e-5** 로, 비율 > 3 이면 학습 로그에 경고.

### 기하 절제 (`scripts/eval_geometry_ablation.py`, 홀드아웃 94샘플)

| 조건 | loss |
|---|---|
| real (이 샘플의 기하) | 0.928 ± 0.170 |
| shuffled (다른 샘플의 기하) | 0.902 ± 0.168 |
| none (주입 없음 = 베이스) | **2.493** ± 0.509 |

- shuffled − real = **−0.026 ± 0.047** · real 이 나은 샘플 **50.0%** · 대조군 같은 격자 72.3% (신뢰 조건 충족)
- none − real = **+1.565 ± 0.467**
- **판정: 기하를 신호로만 쓴다 — 내용은 무시.**

답 유형별로 봐도 같다 — 손실 감소(none − real)는 모든 유형에서 크고 짧은 답일수록 크다
(예/아니오 +5.2 · 수치 +2.9 · 서술 +1.5 · 선택형 +1.1), shuffled − real 은 전부 ±0.04 안.

**무엇을 배웠나 — 생성해 보면 바로 보인다** (홀드아웃, greedy):

| 정답 | none (베이스) | real | shuffled |
|---|---|---|---|
| `C. the right` | `A` | `C. the right` | `C. the right` |
| `C. back-left` | `B` | `D. right & forward` | `D. right & forward` |
| `yes` | `Let's break this down carefully. We are given…` | `yes` | `yes` |
| `False` | `Let's break this down: - The "thing behind…` | `True` | `False` |
| `1.35` | `0.4` | `1.2` | `1.2` |

프로젝터가 배운 것은 **Sensenova 의 답 형식**(선택지 문자 + 보기 문구, 짧은 예/아니오)과
**답 분포**(거리 1m 안팎)다. 기하와 무관한 상수 신호로 LLM 의 출력 습관을 바꾸는 **소프트 프롬프트**처럼
동작한다. 주입 경로가 학습 가능한 유일한 통로라서, 가장 싼 손실 감소(형식)부터 가져간 것이다.
4절의 게이트 1 교란과 **같은 현상이 학습 쪽에서** 나타난 것.

**함의** (이 규모 — 905샘플 · 114스텝 — 에서의 결과다. 83만 건에서 내용이 쓰이기 시작할지는 모른다):
1. S1 의 손실 감소·게이트 1 통과는 기하 효과의 증거가 **아니다.** 절제의 shuffled 조건만이 판정한다
   — 도구는 설계대로 작동했다 (실모델·실데이터로 처음 확인).
2. 형식을 기하 경로 밖에서 흡수시키는 설계가 필요할 수 있다 — 예: 기하 없이 LoRA 로 형식을 먼저 배우게
   하거나(형식 흡수 단계), LoRA+프로젝터를 함께 학습하면서 기하를 일부 샘플에서 빼는 방식(기하 드롭아웃),
   또는 **같은 조건에 shuffled 기하로 학습한 대조 프로젝터**를 나란히 돌려 차이를 기하의 가치로 보는 방식.

## 7. 결정 반영 (2026-09-24 오후) — 대조 프로젝터 · 게이트 1 기준선

6절 결과를 보고 사용자가 추천안 두 가지를 채택했다:
1. **기하 효과는 대조 프로젝터와의 차이로 판정** — `train --geom-control shuffled` 로 같은 데이터·스텝·시드에
   **다른 샘플의 기하**를 주고 학습한 프로젝터를 나란히 둔다. 주입 경로로 기하 없이 배울 수 있는 것(형식·분포)은

## 9. CUT3R 장면 지도 프롬프트 — 제로샷 (사용자 방향: 사전학습 지식 활용 + 라이브 1초)

사용자 제안 (2026-09-24): CUT3R 가 상황 프롬프트를 **계속 만들어 두고**, 질문이 오면 바로 답한다 (1초 안).
기하를 새 임베딩으로 넣는 대신 VLM 이 **이미 읽는 형식**(지도 이미지 + 측정값 텍스트)으로 바꾼다.

구현 (`serve/scene_map.py`, `StreamingSession(scene_map=...)`, `eval_vsi_local.py --scene-map`):
- CUT3R 헤드로 점맵(첫 프레임 좌표계)·신뢰도·카메라 포즈를 뽑아 누적 → 카메라 "위" 평균으로 세우고 벽에 맞춰 돌린
  위에서 본 지도 (1m 격자, 카메라 궤적, 키프레임 번호, 마지막 시선 화살표) + 측정값 (방 가로×세로·면적, 높이, 이동 거리).
- 지도는 키프레임 **뒤**·질문 **앞**에 이미지로 (주입 없음), 측정값은 텍스트로 → 프리픽스 캐시에 미리 들어간다.
  질문 시점 비용은 질문 토큰뿐 (질문만 TTFT 는 지도와 무관).
- **CUT3R 재현 검증**: 프레임 단위 우리 재현(`ingest` + 헤드) vs 원본 `forward_recurrent` — 실제 VSI 영상 6프레임에서
  점맵·신뢰도·포즈 **max|Δ| = 0.0** (`scripts/check_cut3r_stream.py`). 재귀 상태·포즈 조회·메모리 갱신·헤드 입력이 원본과 같다.
  (헤드는 CUT3R 의 transpose_to_landscape 래퍼로 감싸져 `[B,2]` 텐서를 받는다 — 튜플을 넘겼다가 여기서 잡혔다.)

스모크 (4B 베이스, 영상 4개 · 96문항, 비디오 모드):
- **방 크기는 측정값을 그대로 옮겨 답한다** — 정답 4.2 / 22.2 / 20.4 → 지도 측정 5.0 / 20.3 / 18.9 → 답 5 / 20 / 19.
  한 곳(ARKit, 정답 21.3)은 측정이 34.1 로 과대 → 답 34. 정확도는 측정 품질에 달렸다.
- **지도·텍스트가 앞에 붙으면 선택형 형식이 깨진다** (실패 31%, `"To determine the position…"`) — 이미지 모드와 같은
  현상. 텍스트 끝에 "지도를 참고하되 요청한 형식으로 바로 답하라" 한 줄을 넣자 **0%** 로 돌아왔다.
