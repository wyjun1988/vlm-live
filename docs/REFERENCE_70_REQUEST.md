# 레퍼런스(VSI 70.83) 시스템 추가 정보 요청

**대상:** Qwen3.5-4B + LoRA `ckpt/cot/qwen3.5-4b-allcot-sqa-gt-cut3r-lora2` (VSI-Bench 70.83) 를 만든 팀
**작성:** Live3R (wooyeol), 2026-10-01

## 왜 요청하나

같은 설계(CUT3R → merger → 입력단 게이트 융합, LoRA, 같은 학습 데이터)를 **우리 코드로 새로 구현**해서 70점 수준을 먼저
재현하고, 그 다음 라이브(스트리밍 입력, 질문 후 1초 안 답변) 형태로 옮기려고 한다. 파일에서 읽을 수 있는 건 이미 다
맞췄고(아래 "이미 아는 것"), 남은 건 **사람에게 물어야만 알 수 있는 설정값·샘플·결과**다.

**코드는 필요 없다 — 보내지 말아 달라.** 설정값, 출력 샘플, 결과 숫자만 있으면 된다.

## 받는 방법

- 텍스트 파일 하나에 항목 번호별로 답을 적고, 이미지가 필요한 항목(1번)은 파일로 같이 주면 된다.
- 공유 볼륨이면 `/group-volume/wooyeol/vlm-live/outputs/reference_answers/` 에 두거나 wooyeol 에게 전달.
- 모르는 항목은 "모름"으로 두면 된다. 숫자 하나라도 있으면 도움이 된다.

## 우선순위 A — 학습 시작 전에 받으면 바로 반영 (run 3 대기 중)

### 1. 모델에 실제로 들어가는 입력 샘플 (템플릿 확인)

학습 데이터로더가 만든 샘플 3개와 평가 입력 1개:

| 샘플 | 데이터 |
|---|---|
| a | vlm3r_scannet (32프레임 레코드) 1개 |
| b | spar_234k 중 `spar_info` 마크가 있는 레코드 1개 — **마크가 그려진 이미지 1장(png)도** |
| c | llava_hound_64k (프레임 폴더 비디오) 1개 |
| d | VSI-Bench 평가 문항 1개 |

각 샘플마다:
- `input_ids` 를 tokenizer 로 decode 한 **전체 텍스트** — 연속된 이미지/비디오 패드 토큰은 `<|image_pad|>×192` 처럼 개수로 줄여서
- 학습 샘플은 **라벨이 -100 이 아닌 구간**(학습하는 부분) 표시
- `image_grid_thw` (또는 이미지별 토큰 수)와 각 이미지의 최종 해상도(H×W)

이걸로 확인하려는 것: 시스템 프롬프트 유무, assistant 앞의 빈 think 블록(`<think>\n\n</think>`) 유무, CoT 레코드에서
`<think>` 블록이 들어가는 자리, 비디오 프레임에 타임스탬프가 붙는지.

### 2. 학습 해상도와 프레임 규칙

- 이미지 1장 레코드와 여러 장(32프레임) 레코드의 **프레임당 토큰 수** (min/max pixels 값). 같은 규칙인가?
- llava_hound 같은 **프레임 폴더 비디오**: 몇 장을 어떤 간격으로 뽑나(fps 를 몇으로 가정하나)? 이미지로 넣나, 비디오(temporal patch)로 넣나?
- **CUT3R 입력 해상도**(긴 변 512?)와 비전 입력과의 관계(같은 크기로 리사이즈?), CUT3R 연산 정밀도(fp32/bf16)
- `model_max_length` 12800 을 넘는 샘플: 자르나, 버리나?

### 3. 기하(CUT3R) 경로 세부

- CUT3R 의 **어떤 출력**을 쓰나: 마지막 디코더 층(768차원)이 맞나, 마지막 정규화(dec_norm) 전인가 후인가? 카메라(포즈) 토큰은 빼나?
- merger 의 **2×2 병합 토큰 순서**: 네 토큰을 어떤 순서로 이어 붙이나(예: (0,0),(0,1),(1,0),(1,1) 행 우선)? `ln_q` 는 병합 전 768차원 토큰마다 적용하는 게 맞나?
- CUT3R 격자와 비전 토큰 격자를 어떻게 맞추나: 같은 해상도라 1:1 인가, 보간하나?
- 한 샘플의 여러 프레임: CUT3R 를 **프레임 순서대로 상태를 이어서** 돌리나(첫 프레임 기준), 샘플마다 리셋하나? 이미지 1장 레코드는?
- 융합 게이트: 입력 순서가 `[norm1(비전); norm2(기하)]` 인가? `gate_projection` 의 초기화(가중치·bias)와, 학습 시작 시 게이트 값(대략 0.5?)
- 비디오 모드 입력(2프레임 = 1 temporal patch)일 때 기하 토큰을 2프레임씩 어떻게 합치나? (평가가 비디오 경로라서)

### 4. 다른 학습 실행들의 결과 표

지금까지 학습한 모델들의 **VSI 점수(전체 + 유형별)**와 각 모델의 설정:

| run 이름 | 데이터 믹스 (CoT 포함? SQA3D/ScanQA 포함?) | 융합 (gt / gtwn / 기타) | 스텝·에폭 | VSI 전체 | 유형별 |
|---|---|---|---|---|---|

특히 알고 싶은 것:
- **CoT 없는 "all" 믹스**(예: `train_qwen35_4B_all_gt*`) 결과 — 우리는 라이브라서 CoT 를 빼고 학습한다. CoT 를 빼면 몇 점이 되는지가 우리 목표치다.
- **gtwn**(게이트 융합에서 정규화 제외) 결과 — 우리 비교 조건 하나와 같다.
- Sensenova 만 쓴 것, VSI-590K 를 쓴 것, 기하 없이(plain SFT) 같은 데이터로 학습한 것이 있으면.

결과 JSON 파일 경로 목록만 줘도 된다 — 표는 우리가 만든다.

## 우선순위 B — 언제든

### 5. 평가 세부
- VSI 32프레임을 비디오 모드로 넣을 때 **총 비전 토큰 수**, CUT3R 를 32프레임 전부에 돌리나?
- **라이브에 가까운 설정**으로 평가해 본 적이 있나: 1fps 샘플링, 프레임을 이미지로(`vsibench_multiimage`), 낮은 해상도(`TARGET_SIZE`), 프레임 수 제한. 있으면 그 점수.
- 같은 체크포인트를 다시 평가했을 때, 또는 시드를 바꿔 다시 학습했을 때 점수 편차.

### 6. 일반 능력
- 70.83 모델과 베이스 Qwen3.5-4B 의 **VideoMME / MMStar**(또는 다른 일반 벤치) 점수. 우리 기준은 VideoMME 가 베이스 대비 −1.0 이내.

### 7. 학습 환경
- `pip freeze` 한 장 (특히 torch, transformers, flash-attn, deepspeed, flash-linear-attention, peft, accelerate), CUDA·드라이버 버전
- DeepSpeed 설정(ZeRO-2 json 의 값), dataloader worker 수
- 노드당 처리량(로그의 6.48 샘플/초)을 어떻게 쟀나 — 우리는 같은 클러스터에서 0.5 샘플/초가 나와 원인을 찾는 중이다.

### 8. 학습 곡선
- 중간 체크포인트(예: 1/4, 1/2, 3/4 지점)의 VSI 점수가 있으면. 데이터를 얼마나 봤을 때 몇 점인지 알면 우리 학습 길이를 정할 수 있다.
